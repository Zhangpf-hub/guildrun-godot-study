# 移植技能动作特效

从项目根目录工作，Godot 工程在 `game/`。先用原版与 Godot 各跑一遍同关卡、同阵容、同种子的战斗。记录施法、伤害、位移、落格和结算的模拟步，从起手到收招连续截帧。标明截图分辨率和原版帧号的估计误差，以动作与命中作交叉校对。

1. **沿事件找资源。** 从角色 prefab 的 `VfxHandlerComponent` 找动作事件关联的特效组件，再追到实际启用的发射器、挂点、材质和贴图。检查 GameObject、Renderer 与 Emission 模块是否启用，以及播放组件何时激活根节点。粒子系统的 Trail 模块和独立的 `TrailRenderer` 都能画拖尾，沿组件类型核实来源。记下资产文件与 PathID。动画骨骼轨、特效延时、发射器延时和伤害定步各自记录。比较连续帧，确认粒子应随骨骼移动、随棋子位移，还是留在发射位置。
2. **按原版渲染路径装配。** 核对实际前向渲染通道的混合和深度写入，再检查 shader variant、顶点流、纹理通道、HDR 强度、深度淡出和透明排序。用 Renderer Feature 的层掩码、队列和 Camera Settings 核对普通透明与后续重绘是否都覆盖同一发射器。重绘时复用已经出生的粒子与寿命数据，并单独核对覆盖后的投影和背景深度。发光强度有差异时，分别核对材质颜色属性的上传值、粒子 Renderer 的顶点色转换和场景泛光。可以用浮点渲染目标读取材质上传结果。序列图从原版 UV 模块读取网格、寿命进度曲线与周期。记录各发射源的爆发批次、按时间或距离计算的发射率，以及模拟空间和缩放模式。出生尺寸和颜色按发射器时间采样，溶解与透明度按粒子寿命采样。网格方向有差异时，用 Unity `ParticleSystemRenderer.BakeMesh` 测量三轴、广告牌轴心偏移和 UV，再核对 Godot 的旋转顺序与 FBX 挂点朝向。对同一时刻的多层效果逐层截图，先定位差异再调参。
3. **接入正常战斗入口。** 复用 `game/battle/board_unit.gd` 的动作入口以及现有粒子和材质代码。确认技能取消、角色死亡、暂停、倍速和结算时如何清理或推进表现。保留 `encounter.gd` 作为伤害、目标和棋盘位移的定步权威。战斗结束时，分开记录最后一个模拟步和结算前仍在播放的渲染帧。在编辑器打开时，使用项目现有 GodotIQ 工作流处理场景、导入与校验。
4. **回归并保留证据。** 先校验触发时间、发射数、纹理帧推进和挂点。保存后重新加载场景，核对材质参数与场景计时字段的值和类型。浮点字段即使取整数值也要写成 `3.0` 这类浮点字面量，避免场景重存时回退到默认值。验证自定义顶点流时同时导入曲线键与倍率，用 `GetCustomParticleData` 和烘焙网格核对材质实际收到的分量。对照帧可以只隐藏单个渲染层，同时保留动画与表现时钟，核对该层造成的画面变化。需要校准发射时刻时，分别验证挂点取样和各层的起播时刻，尤其注意角色是否在两者之间发生位移。再比较起手、命中峰值、残留和收招，复跑战斗统计与战后结算。记录对应源码和截图，以及根据实机画面作出的近似。若只移植了某个事件，写明覆盖的阶段与尚未接入的阶段。

批量移植时按[Dragomir 装配与批量验收](references/dragomir-action-port.md)的方式先完成一个普通事件链。用 REA 定位本构建的运行时分发，再用资产 PPtr 追踪具体组件实例。每个 VisualConfig 记录默认、等级变体、缩放分支、弹道预制体及独立命中特效。普通角色根节点挂点可走 `game/Characters/action_vfx/<visual_id>.json`。按事件记录已接入、部分接入、专用入口或证据缺失，原版数组为空时再检查能力的独立播放路径。

同一个发射器有两遍绘制时，把计算出的颜色、寿命、序列图和自定义数据都上传到两份材质。复制材质后直接截帧曾导致黑色发光层以默认白色绘制。切换重绘做对比时，只移除发射器对应的 `next_pass`，保留普通透明材质及另一个 Renderer Feature。使用同一帧和相机检查重绘顺序，再用原版截图核对余下的发光和动画差异。

排查高亮外圈时，先只隐藏可疑发射器，再只关闭泛光并保留曝光和调色。分别记录亮芯面积、外圈颜色与固定采样区的误差。对空网格和静止尾迹，先用相机读回和烘焙三角形面积确认是否存在可见覆盖。

着色器读取了烘焙网格缺少的顶点通道时，在原渲染后端把各输入分量写进独立颜色通道并读回浮点目标。用显式绑定零值再测一次，核对引擎是否从已有通道补值。结合原片元程序的阈值、默认纹理和混合状态验证像素贡献。可以复用[命中白芯顶点流探针](scripts/CoreWhiteStreamProbe.cs)和[读回着色器](scripts/CoreStreamPixel.shader)。

细轮廓和翻页图集在远景出现锯齿时，核对原贴图的 mipmap、环绕模式和 sRGB 标记。保留原始压缩 mipmap 时，逐级比对解码后的像素。翻转 BC3 贴图时，块内的颜色与透明度索引都要翻转。再在战斗场景读回实际材质使用的 mipmap 数量，并用分层测试贴图检查原采样器是在单级内插值，还是混合相邻级。用同帧对照区分贴图边缘变化与角色动作变化。

核对入场和收招时，沿战斗事件确认原版由触发器进入控制器，还是直接播放动画片段。在启用控制器过渡的小样中，分别测量两侧动画与混合权重受攻速的影响，再用相同技能时钟和固定镜头比较角色姿势。控制器以标准化时间设定退场时，用原始片段长度换算秒数，并核对 FBX 导入后是否多出末帧。跨过退场时刻的渲染帧应把剩余时间交给新状态。分别检查自然收招、后续动作打断、暂停恢复和战斗定步停止后的画面。
